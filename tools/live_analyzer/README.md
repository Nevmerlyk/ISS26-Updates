# ISS26 Live Analyzer v0.1

Экспериментальный **read-only** регистратор оригинальной ISS Pro Evolution 2 (Europe, SLES03321) для PCSX-Redux. **Не патч игры и не модифицирует память.**

## Что записывает

- **Позиции мяча и 22 футболистов на мини-карте** на каждом событии `GPU::Vsync`. Таблица работает для оригинального матча Германия — Франция; при других составах названия игроков могут быть неправильными. Это **координаты отображения мини-карты**, не доказанные координаты ИИ/физики.
- **Изменения любых байтов основной RAM (2 МиБ)** по сравнению с предыдущим снимком, по умолчанию один раз в **5 Vsync**. Первая RAM сохраняется целиком; изменения записываются как бинарные дельты, группируя соседние изменённые байты. Следующий снимок можно восстановить, применив дельты к исходному.
- Полный снимок RAM по команде `ISS26.capture()` и последний снимок при `ISS26.stop()`.

### Важно понимать ограничения

Анализатор видит **конечные изменения байтов между снимками**, а **не каждую операцию чтения/записи** MIPS. Если один адрес поменялся туда и обратно между сканированиями, такого события не будет. VRAM, SPU RAM, регистры оборудования, DMA-транзакции и память карты не отслеживаются. Для поиска того, **какой код пишет по адресу**, нужны CPU breakpoints и trace. Захват всего RAM каждый Vsync будет замедлять игру; можно поставить `SAMPLE_EVERY = 1` в Lua на коротких тестах.

## Как запустить

1. Открой PCSX-Redux; загрузи исходную европейскую игру. **8MB expansion должен быть выключен**. Debugger включён, CPU желательно Interpreter.
2. Создай на Windows папку `C:\ISS26`. Скачай **[ISS26_LiveAnalyzer.lua](ISS26_LiveAnalyzer.lua)** и положи его в эту папку (не сохраняй как `.lua.txt`).
3. Открой матч **Германия — Франция**. Лучше **CPU vs CPU**.
4. Открой **Debug → Lua → Show Lua Console**. Выполни одну строку:

   ```lua
   dofile("C:/ISS26/ISS26_LiveAnalyzer.lua")
   ```

5. Должно появиться `ISS26 Live Analyzer STARTED`. Запусти/продолжи матч. Для проверки выполните `ISS26.status()`.
6. В конце матча **обязательно** введи `ISS26.stop()`, чтобы закрыть файлы. При желании в интересном эпизоде выполни `ISS26.capture()`.

В папке **ISS26** (`%USERPROFILE%\ISS26`) появятся файлы с одинаковым префиксом, например:

- `ISS26_YYYYMMDD_HHMMSS_baseline_RAM.bin` — снимок 2 МиБ при запуске.
- `ISS26_YYYYMMDD_HHMMSS_RAM_deltas.bin` — запись изменённых байтов.
- `ISS26_YYYYMMDD_HHMMSS_positions.csv` — координаты мяча и футболистов по кадрам.
- `ISS26_YYYYMMDD_HHMMSS_final_RAM.bin` — финальный снимок.
- `ISS26_YYYYMMDD_HHMMSS_readme.txt` — метаданные сеанса.

**ZIP этих файлов можно отправить в чат для анализа.** Не нужно отправлять образы оригинальной игры ещё раз.

### Команды в Lua console

- `ISS26.status()` — статистика.
- `ISS26.capture()` — отдельный снимок RAM.
- `ISS26.stop()` — закончить и сохранить данные.

Повторное выполнение `dofile(...)` остановит предыдущую запись и создаст новый сеанс. Не перезапускай эмулятор до `stop()`, чтобы не потерять буферизированную запись.

## Формат RAM-delta

Бинарный файл начинается с 8 байт `ISS26D1\\0` (последний байт — NUL). Затем:

| Поле | Тип | Значение |
|---|---|---|
| Vsync | uint32 LE | Номер Vsync с момента запуска регистратора |
| Offset | uint32 LE | Смещение в 2 МиБ RAM |
| Length | uint16 LE | Число изменившихся подряд байтов (1–4096) |
| Payload | Length байт | Новые значения байтов |

Незаписанные адреса не изменились между двумя сканированиями. Пример использования декодера (для анализа на ПК с Python):

```powershell
python tools/live_analyzer/decode_iss26.py "C:\Users\USER\Downloads\ISS26_..._baseline_RAM.bin" "C:\Users\USER\Downloads\ISS26_..._RAM_deltas.bin"
```

Первоначальный поиск мини-карты основан на трёх дампах RAM пользователя. Зафиксированные смещения: `0x549A6` (запись мяча), далее 23 записи с шагом 10 байт, X/Y в байтах +6/+8, signed int16 LE.
