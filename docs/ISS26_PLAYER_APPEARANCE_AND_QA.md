# ISS26 player appearance and data QA (draft, 2026-11-16)

## Data model
Canonical player identity: stable internal player_uid; link verified FM UID only after matching name, DOB, and country/club evidence. Club and national team rows reference the same person. A roster selection is separate from attribute version. Retired legends are timeless separate profiles (historical peak date), not current FM26 substitutes.
- Player: display name, aliases, DOB, age at 2026-11-16, height_cm, weight_kg, preferred foot, left/right-foot ability, position list, source/date/confidence per field.
- Roster: team_id, player_uid, selection_status, shirt number, source and snapshot date. A player's number is specific to a team. Never infer squad selection from FM's old club field. 54 national, 4 bonus, 24 clubs; 22 playable slots each.
- Appearance record per player: reference_page, reference_date, portrait_path (local only, subject to rights), image_sha256, face_shape, skin_tone_observed, hair_style, hair_color, facial_hair, facial_hair_color, body_build, accessories, boots, reviewer, verification_status. Unknown is null. Skin tone is a visual texture descriptor, not ethnicity; never infer it from country, name or FM ethnicity labels. Do not scrape facial biometrics or identify unnamed faces. Only annotate named official player profiles with reliable contextual identity. Public profile URLs are pointers, not permission to redistribute images.
- FM raw 1–20 and derived ISS candidate 12–19 fields must remain separate. Validate supported ranges and exact bit layout against PAL ISO before release. If no reliable value, report missing; no guessed or borrowed data. Current age computed from DOB; legend age fixed at defined historical snapshot. Preserve original weight, height and both feet values if observed. If ISS cannot store a field, keep it in the external master.
- Positions: GK→GK; DC→CB; DL/DR/WB→SB; DM→DH; wide M→SH; AMC→OH; AM R/L→SH or WG depending on FM familiarity/role; ST→CF. MC may be DH or OH. Retain side and alternatives; no arbitrary primary position for ambiguous profiles.

## Academy/Explorer tasks
1. Build a fresh original PAL player appearance catalog. Through Edit Player, change one visual option at a time. Compare RAM before/after, locate serialized record and bit mask; repeat on at least two player slots; capture in-game screenshots and GPU/VRAM on the same camera/lighting. Record only observed values and addresses, do not use undocumented preset IDs.
2. Catalog each valid template with screenshot, head and hair mesh/texture identity, palette, facial hair, body sizing and accessories if exposed. Save template IDs and tested masks as JSON. A selector may affect animation or shared texture; verify isolation.
3. Assign nearest supported preset from manually reviewed appearance descriptors, prioritizing hair silhouette, skin palette, facial hair, facial contour. Use documented height/weight to choose approximate supported body build only if legal encodings are known; do not use BMI as direct athletic physique. Keep unmatched aspects in master. Preserve original mechanics if a slider is absent.
4. For key players, where generic presets are insufficient, research native texture format, CLUT and UVs; create original/relicensed low-resolution replacements, preserve texture dimensions/format and VRAM limits, and test for unintended changes. No actual face texture patch has been produced by this draft.
5. Validate team/club duplicate consistency, 22 roster entries per team, correct shirt numbers if sourced, no invalid mask and no cross-slot corruption. Verify close-up, normal match camera and restart on clean original (no previous patch dependency). Academy captures and reports per session. Release gate: no missing required attributes, no unmatched IDs or unsupported IDs, separate verified and draft artifacts.
